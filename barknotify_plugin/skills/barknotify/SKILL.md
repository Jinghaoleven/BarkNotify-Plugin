---
name: barknotify
description: Set up or troubleshoot BarkNotify-Plugin session notifications, change notification preferences, or send a Bark push when the user requests it. Automatic session notifications run through lifecycle hooks.
---

Prefer the bundled `../../scripts/barknotify.py` relative to this skill directory: `python3 <script> <command>`. A global `barknotify-plugin` is optional and exposes the same commands. Both need Python 3.11+ and curl; do not install a separate CLI solely for setup.

For requested setup, run `status` first. If this marketplace plugin lacks an integration record, run bundled `integrate` to connect it without replacing its marketplace source. Reuse existing settings and credentials; retain an existing tool-managed installation method. Guide the user to open Bark on their iPhone and allow notifications. Have them run `setup` in their own local terminal and enter their push URL or device key privately; never request a credential in chat or feed it through a logged agent tool. Input is hidden and a full URL selects its server automatically. `setup --integrate` combines marketplace integration and private configuration. `setup --key-stdin` supports a local password-manager pipe.

`setup` sends a verification push and enables delivery after server acceptance; `--no-test` explicitly skips this. Server acceptance does not prove the phone displayed it. Confirm phone delivery with the user, then review hook trust and verify one natural turn-ending notification after restarting. Report any pending phone action or restart rather than claiming completion. Credentials are stored separately from settings, with private permissions, outside the cache. An environment variable named by `device_key_env` overrides the saved key.

Default events are `turn.completed` and `approval.required`. Use `events` to list optional events and `setup --events <comma-separated-events>` to choose them. `setup --language en|zh` selects notification language. `enable` and `disable` toggle automatic delivery. Run `test` for a requested delivery test, or `send --title <title> --body <body>` for a requested one-off notification. These commands send actual pushes.

Installation uses a standard Codex marketplace and bundled hooks. `integrate` refreshes an installed plugin from its existing source, detects native hook support, and may register a stable compatibility bridge in the target home's `hooks.json`. `install` creates a tool-managed local marketplace and refuses to overwrite an existing native marketplace installation. For Git updates: `codex plugin marketplace upgrade barknotify-plugin`, then `codex plugin add barknotify@barknotify-plugin`, then bundled `integrate`. For local marketplaces, update the checkout and skip marketplace upgrade. An optional global CLI updates separately.

The bridge follows the native user plugin switch and cache, so disabling or removing Bark in `/plugins` stops pushes. Use `uninstall` before native removal if the cached script is your cleanup entry. Otherwise use the checkout or CLI afterward. Never bypass trust. After installation or upgrade, open `/hooks` in a new session to review scripts. `doctor` checks registration and trust without sending pushes or starting a model turn; it cannot verify phone display.

Settings default to `${XDG_CONFIG_HOME:-~/.config}/barknotify-plugin` and can be overridden with `--config-dir` or `BARKNOTIFY_CONFIG_DIR`. A managed install records its chosen settings in `$CODEX_HOME/bark-install.json`; the CLI and hooks discover them automatically. Independent Codex homes can use separate settings, while provider launchers sharing a home share one plugin installation. No provider-specific integration is required.

Stop means this turn stopped, including when the agent asks a question; it does not prove task success. PermissionRequest runs before any automatic reviewer resolves the request; disable `approval.required` if it is noisy. SessionEnd follows runtime session lifetime, which may outlast a CLI client. Delivery is best effort and cannot report a force-killed process or an unreachable server reliably. Hooks return neutral JSON and never decide approvals. Automatic pushes omit prompts, responses, commands, approval reasons, complete paths, and session identifiers; names, project basename, model, and tool metadata may appear on the phone.
